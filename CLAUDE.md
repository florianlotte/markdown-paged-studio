# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` / `npm run build` / `npm run preview` (Vite, entry is `index.html`). `vite.config.js` only defines two build-time constants, `__APP_VERSION__` (from package.json) and `__APP_COMMIT__` (`GITHUB_SHA`, else `APP_COMMIT`, else git), read through `src/version.js` and shown in the sidebar footer; the dev server shows `dev` as the commit. Restart a running dev server after editing `vite.config.js`. `PORT=5183 npm test` runs the web suite next to a dev server that already holds port 5173. `npm test` is Chromium only; `npm run test:firefox`, `npm run test:webkit` and `npm run test:browsers` (all three) need `npx playwright install firefox webkit`. `SLOWMO=300 npm test` pauses before every action, as the slower machines of the CI do: an assertion that only passes because it reads the page before a render has finished (a page count equal to the one before the change, for instance) fails there; wait for `#preview` to lose `.is-stale` before such a read. Run the engines one after the other, never at once: they share `test-results/` and the Vite cache. On this kind of machine without sudo, WebKit runs with `PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1` once its missing libraries are linked into its `minibrowser-wpe/sys/lib`. Use `npm test -- -g "part of its title"` for one test: a bare `npx playwright test` runs the three engines.
- `npm run lint` (ESLint flat config, browser globals) and `npm run format` (Prettier: 2-space, single quotes, semicolons, width 120). Both must pass before you finish.
- `npm test` runs the Playwright integration tests in `tests/studio-*.spec.js`, one file per domain (document, layout, diagrams, images, editing, features, files, language) with shared helpers in `tests/helpers/studio.mjs` (the editor is a CodeMirror view: tests read and write the Markdown through `expectMarkdown()`, `setMarkdown()`, `focusEditor()`, `cursorToEnd()`, backed by `window.studio.editor` and `window.studio.markdown()`; write redo as `Control+Shift+Z` with an uppercase key, Playwright otherwise sends a lowercase `z` that CodeMirror reads as undo; headless Chromium, starts Vite itself; one-time `npx playwright install chromium --only-shell`). Most of the app needs a browser (Paged.js, FileReader, Blob URLs); the pure Markdown, image and font helpers have unit tests in `tests/markdown.test.mjs`, `tests/images.test.mjs` and `tests/fonts.test.mjs`, next to `tests/files.test.mjs` for the files of a document, `tests/math-core.test.mjs` for the formulas, `tests/pdf-sources.test.mjs`, `tests/markdown-sources.test.mjs` and `tests/archive.test.mjs` for the sources carried by exports, `tests/repo.test.mjs` for the changelog, `tests/conformance.test.mjs` for the Markdown conformance, and `tests/crossref.test.mjs`, `tests/escape.test.mjs`, `tests/diagram-labels.test.mjs`, `tests/prettify.test.mjs` for those helpers (`npm run test:unit`). Use `/verify-preview` for visual checks. `npm run screenshots` (after `npm run build`) retakes the README screenshots with `scripts/screenshots.mjs`; run it when the look of the studio or of the sample document changes, from a build without personal files in `local/`. A dev or preview server started for a check must be stopped afterwards (never the user's own server on port 5173).
- Desktop build: `electron/main.js` (ESM) serves `dist/` over the private `app://studio` scheme and exposes only `window.desktop.exportPdf`, `window.desktop.writePdf` and `window.desktop.onCommand` (File and View menus) through `electron/preload.cjs` (sandboxed renderer). `standaloneHtml({ mode })` takes `export`, `print` or `pdf`. `exportPdf({ project })` picks the direct desktop path (`exportPdfDirect()`), and in the browser `exportPdfRendered()` with the project or `openPrintWindow()` (print dialog) without it; `openPrintWindow()` must stay inside a user gesture (click, Ctrl+P) with `window.open` before its first `await`; the desktop test is `npm run test:desktop` (needs `npm run build` first, own config `playwright.desktop.config.js`). Packaging: `electron-builder.yml`, output in `release/`.
- MCP server: `mcp/server.mjs` (stdio, `@modelcontextprotocol/sdk` + Playwright) renders through `dist/` using the page automation API `window.studio` from `src/automation.js` (`defaults()`, `schema()`, `render(config, mode, { images })`). Keep that API and the zod `configShape` of the server in sync with `CONFIG_SCHEMA`. `MPS_OUTPUT_DIR` confines the tools' writes, `MPS_INPUT_DIR` the image files they read (both compared as real paths, so a symbolic link cannot lead outside), existing files are only replaced with `overwrite: true`, and the browser context aborts every request outside `dist/`. Test: `npm run test:mcp` after `npm run build` (Node test runner, real MCP client over stdio).
- Releasing (CONTRIBUTING.md has the full procedure): move the `Unreleased` entries of `CHANGELOG.md` under `## [x.y.z] - date`, add its compare link at the bottom, and bump `package.json` to the same version (`tests/repo.test.mjs` fails otherwise); the release notes are cut from that section by `scripts/release-notes.mjs`. Describe every user-visible change under `Unreleased` as part of the change itself.
- Workflows: `ci.yml` is also a reusable workflow. `release-desktop.yml` waits for the CI run of the tagged commit (`gate` job) and only calls `ci.yml` itself (`checks` job) when the commit has none, before building, and `pages.yml` runs on `workflow_run` after a successful CI on `main`, so nothing is deployed or released from a commit that fails the tests. Keep the workflow name `CI`: `pages.yml` refers to it.

## Constraints

- 100 % client-side: no backend, no env vars. Personal defaults come from the gitignored `local/` folder, read at build time with `import.meta.glob` and merged into `DEFAULTS` (never into `DEFAULT_STATE`); use `DEFAULTS` for anything that resets or initializes the document. The document autosaves to localStorage (`STORAGE_KEY`), except `logoDataUrl`, which is saved in IndexedDB (`restoreLogo()`, `saveLogo()`; still a plain state key in the config JSON and the MCP config), and every config that enters the state (JSON import, restore) goes through `mergeConfig()`, which runs `sanitizeConfig()` (whitelisted keys, coerced values) and keeps the two forms of the text consistent: `state.files` (`[{ name, markdown }]`, the source, edited as tabs) and `state.markdown` (their assembly, what is rendered, exported and given to the MCP server). A config with only `markdown` becomes one file; `files` win when both are there; only the files are autosaved. A new state key needs: a default in `DEFAULT_STATE`, a kind in `CONFIG_SCHEMA` (validated in `sanitizeConfig()`), a form control with the same `id` in `index.html` (bound automatically by `bindInputs()`; `language` and `logoDataUrl` are the exceptions, bound in `settings.js`), its French label in `src/i18n.js`, and an entry in the MCP `configShape`.

## Paged.js gotchas

- Preview creates a fresh `new Previewer()` per render (220 ms debounce) into a hidden but attached `.render-stage`, then swaps the pages into `#preview`. A newer render cancels the pending one with `cancelPreviewer()`: `chunker.stop()` alone is not enough, Paged.js 0.4.3 resumes a stopped render (`flow()` calls `start()` and renders again), so `start` is made to throw and `preview()` rejects. A render whose HTML and CSS equal the last ones shown (`lastRendered`) keeps the pages; the interface language change rebuilds the tools with `refreshPreviewTools()` instead. `disposePreviewer()` removes the `<style>` each Previewer injects into `<head>`. Paged.js itself is loaded on demand (`lazy`) for the first render. Never render straight into `#preview`. CSS is handed to Paged.js as a Blob URL.
- Print and HTML export (`standaloneHtml()`) inline `paged.polyfill.min.js` from node_modules through a Vite `?raw` import, so the export works offline and always matches the bundled version. The print window prints itself from `PagedConfig.after`, never from a timer.
- markdown-it runs with `html: false`: raw HTML in Markdown is intentionally stripped.
- Mermaid diagrams are rendered to inline SVG in `renderDiagrams()` before pagination and are part of the HTML handed to Paged.js and to the export. `documentHtml()` parses the rendered HTML once into a `<template>` (`fragmentOf()`, inert: images are not decoded) that `renderDiagrams()` and `highlightCode()` edit in place (both also accept a string), and serialises it once; coloured code blocks are cached by theme, language and text. Labels are SVG text (`htmlLabels: false`, more reliable in print): Mermaid only understands `<br>` there, so `diagramSvg()` runs the source through `markLabels()` and the SVG through `styleLabels()` (`src/diagram-labels.js`). `documentHtml()` and `standaloneHtml()` are async; the print handler must call `window.open` before its first `await` or pop-up blockers will stop it.
- Diagram size lives in the Markdown (` ```mermaid width=60% align=left `), never in UI state: the preview controls rewrite that fence line through `updateFenceAttributes()` using the placeholder's `data-line`. Target a diagram's drawing with `.mermaid-diagram > svg` (the controls contain icon SVGs), and keep the controls out of `documentHtml()`. While a render is pending the preview is `.is-stale` and the controls are inert. The controls show on hover (with a CSS bridge over the gap to the toolbar and a grace delay through `visibility` transitions, never `pointer-events: none`) and stay open on the clicked diagram (`.is-selected`, remembered by source line across renders). Test pointer travel with `page.mouse.move(..., { steps })` after scrolling the diagram into view: `hover()` and `click()` teleport and hide this class of bug.
- Images never use their path: the `image` rule of `src/markdown.js` resolves the file name through `findImage()` and inlines the data URL, or renders `.image-missing`. They live outside `state` (IndexedDB, plus the `images` key of the config JSON), so extend `exportImages()`/`replaceImages()` rather than `CONFIG_SCHEMA`. Size and alignment are written in braces after the image and rewritten by `updateImageAttributes()` from `data-line`, `data-line-end` and `data-index` (table cells have no source map: their images use the line of their row and a rank across the row). `.is-block` (alone in its paragraph, links ignored) is centered by default; an image inside text floats with `align=left|right` and takes its own line with `align=center`. In `resize-controls.js` measure against `columnBox()` (content box of the nearest non-inline ancestor), never `parentElement`.
- Editing the Markdown for the user: anything the studio writes into the document goes through `src/editor.js` as a CodeMirror transaction (`writeFile()` for the smallest changed range of a file, `insertBlock()` at the cursor), so it lands in the undo history of its file whether the editor is visible or not, and without moving the focus. Line-based tools (resize controls, preview undo) work on the assembled `state.markdown`; `writeDocument()` in `src/chapters.js` attributes their edit to the file that holds the lines (`applyAssembledEdit()`), shown or not. Preview edits (`applyMarkdown()` in `src/render.js`) are also recorded in a history of their own, so Ctrl+Z / Ctrl+Y outside text fields undo and redo them as long as the source was not edited since. A handle driven from the keyboard is refocused after the render (`keyboardKey`). The Insert menu and the image list call `revealEditor()` first, so the user sees what was inserted; `insertBlock()` puts a blank line before and after the block when text is there. An empty file shows the placeholder set by `setEditorPlaceholder()` from `chapters.js` (translated on language change). The tabs are redrawn when the file changes: a click on the current tab must not redraw them, or the double-click that renames lands on a detached element.
- Source lines: for the preview only (`documentHtml({ sourceLines: true })`), the `source_lines` rule of `src/markdown.js` writes `data-source-line` on every block; diagrams and images already carry `data-line`. `src/sync.js` interpolates between those marks, measures them again when the pages, the zoom or the width change, and lets the pane the user acts on (`driver`) drive the other, so renders and programmatic scrolls never bounce back. Exports must stay free of these marks. `highlightCode()` finds code blocks whatever the order of their attributes.
- Links of the preview never navigate: `bindPreviewLinks()` in `src/ui.js` opens `http(s)` and `mailto` links in a new tab (the system browser on desktop), scrolls to the target of an anchor (`#sec-…`) and ignores relative links.
- Markdown conformance: `scripts/conformance.mjs` (`npm run conformance`) runs the CommonMark examples (`commonmark-spec`) and the GFM extension examples (`tests/fixtures/gfm-extensions.json`) through `md`. Every difference with CommonMark must belong to a cause listed in `CAUSES` (raw HTML off, images by file name, typographer, linkify); `tests/conformance.test.mjs` fails on a difference without cause and names the examples. A new markdown-it rule must therefore only react to its own marker: check with `npm run conformance`. When a difference is wanted, or when a syntax becomes supported, update `CAUSES` or the probes, the recorded figures of the test and `docs/markdown-support.md` (`npm run conformance -- --write`, then `npm run format`). Block rules registered before `paragraph` run after `hr`, `list`, `heading`: they cannot take over those syntaxes.
- Document features: heading ids are prefixed (`ANCHOR_PREFIX`, `sec-`) because the preview lives in the studio page, where a heading named "Status" would otherwise shadow `#status`; `[text](#slug)` links are rewritten to the prefixed id. `[[toc]]` lists the headings after it and gets its page numbers from `target-counter()`, which Paged.js turns into a `counter-reset` on the `::after` of each link. Caption numbers are text, never CSS counters (they restart on every page box). Highlighting is a post-processing step like `renderDiagrams()`, with highlight.js loaded on first use; theme colours live in `documentCss()` after the user CSS and must not use italic (it would pull the italic font files into every export). Mirrored margins use `@page :left` plus `@page cover:left` so the cover stays bare.
- Formulas, alerts and small syntaxes: `markdown-it-sub`, `-sup`, `-mark`, `-deflist` are official plugins; `caret_after_bracket` keeps a `^` after `[` as text so an undefined footnote call is not eaten by superscript. Alerts are a core rule after `block` (a `blockquote` whose first line is `[!NOTE]`… becomes `div.alert.alert-<type>` with a `p.alert-title` in `env.language`). Formulas are `math_inline` (after `escape`; Pandoc's rule plus "not after a letter or a digit") and `math_block` (after `fence`, so before `lheading`), plus the `math` fence: they only output placeholders, `.math.math-inline|block` with the escaped TeX as text. `renderMath()` runs first in `documentHtml()` and replaces them with KaTeX's HTML output (no MathML: one copy of the text for `string-set` and the PDF text layer), wrapped in `<!--math-->…<!--/math-->` so `withoutMath()` can drop it when Inter's subsets are chosen. KaTeX's stylesheet (without its `@font-face` rules) and its fonts never go through Paged.js: a `<style id="mathStyle">` in the page and FontFace objects for the preview (`prepareMathPreview()`), `inlineMathCss()` in `<style data-pagedjs-ignore>` for exports and in the SVG of `pdf-render.js`. The faces are those whose selecting classes appear in the rendered formulas (`neededMathFaces()`). Equation numbers are written as text (a page drawn alone would restart a counter). Depend on the same KaTeX range as Mermaid (`^0.18`), so the build holds one copy (Dependabot ignores the next minor). Element rules of `documentCss()` (`mark`, `sub`, `dt`…) are scoped with `:where(.pagedjs_page)`: the stylesheet is inserted in the studio page.
- Numbering and cross-references (`src/crossref.js` is the pure part: label grammar, ids, words per language, `headingCounter()`): labels are `{#fig:name}` in the braces of an image, the bare word `#fig:name` on a Mermaid fence (braces would break the attribute grammar), `{#tab:name}` at the end of a table caption, `{#eq:name}` after the closing `$$`, `{#sec:name}` or `{#name}` at the end of a heading. `structure_attributes` (core, after `block`) strips heading attributes and turns the paragraph `Table: …` next to a table into a `<caption class="table-caption">` inside it; `cross_ref` (inline, after `escape`) reads `@fig:name`, never after a letter, a digit or `_`; `numbering` (core, right after `heading_anchors`) walks the tokens once, numbers what is labelled or what the settings ask (`env.numberHeadings`: `h1` | `h2`, `env.numberFigures`), then resolves the references, footnotes included. Numbers are text (`.heading-number`, `.caption-label`): CSS counters restart on every page, and the running header and the table of contents read the text. A label always numbers its element, so references work with the settings off, and with the settings off and no label the HTML is byte-identical to before (tests pin it). Equations have one source of numbers, `renderFormulas()`: a labelled formula KaTeX did not number is drawn inside `\begin{equation}`, and the references, written with `(?)` and `data-eq`, are filled there. Ids of the document start with `sec-`, `fig-`, `tab-`, `eq-`: no id of `index.html` may (guard in `tests/repo.test.mjs`).

- Outside Chromium: `probePageDrawing()` (`src/pdf-capability.js`) draws a tiny `foreignObject` SVG and reads a pixel back at startup; when it fails, `exportPdf({ project: true })` calls `openPrintWindow()` first, inside the click, then shows `#exportNotice` once, and `#exportPdfProject` is `aria-disabled`. A drawing that fails midway (`code: 'draw'` from `pageImage()`, or a `SecurityError`) calls `markCannotDraw()`. Tests force that path by making `getImageData` throw in an init script. Engine differences belong in the helpers (`savedAs()` for download names, `|| 0` for `-0`, direct `scrollTop` instead of a long wheel); a test is skipped for an engine only when the behaviour cannot exist there, with the reason in the skip.
- Footnotes use `markdown-it-footnote` for the parsing only: the rule `footnote_notes` removes the block of notes the plugin puts at the end, and `footnote_ref` writes the text of the note in place as `<span class="footnote">`, which `float: footnote` sends to the foot of the page. Paged.js numbers calls and notes with CSS counters, in document order; a repeated call is a plain `.footnote-ref` with the number of the first one. The call is an `<a>` that carries the class of the note, so style it through `.footnote::footnote-call`. `src/ui.css` resets the form styles inside `.preview` (`all: revert` on `input`), otherwise the check boxes of task lists take the look of the studio fields.
- Known Paged.js limit: a single paragraph longer than about two pages makes the layout loop ("Layout repeated" in the console, far too many pages). It comes from Paged.js 0.4.3, not from the studio; keep test documents made of several paragraphs.
- Editable exports: `src/pdf-sources.js` (plain ESM around pdf-lib, loaded on demand in the page, imported by the MCP server) attaches `markdown-paged-studio.json` (the project JSON: `sourceJson()` in `src/ui.js`, `window.studio.source()` for the server) and the Markdown (named after the title with `fileStem()` of `src/files.js`, which also names every export) to a PDF, and reads the JSON back. The HTML export carries the same JSON in `<script type="application/json" id="markdown-paged-studio-source">` (`standaloneHtml({ source })`, `sourcesOfHtml()`). Desktop: the package has no node_modules, so `export-pdf` returns the bytes and a one-shot token for the chosen path, the page attaches the sources, and `write-pdf` writes them; the page never sees the path. `Export` is a split button (`#exportDefault`, `#exportMenu`, `#exportOptions`): the main part (and `Ctrl+Shift+E` on desktop) exports the PDF with the project, `Ctrl+P` prints the document (the print window in the browser, File → Print on desktop); the menu offers `PDF with project`, `PDF only`, `HTML with project`, `Markdown with project`, `Markdown files (zip)` and `Project only` (`exportPdf({ project })`, `exportHtml()`, `exportMarkdown()`, `exportArchive()`, `exportProject()` in `src/ui.js`). The zip (`src/archive.js`) holds the files, `style.css`, the logo and the images as plain entries and the settings in `markdown-paged-studio.yaml`; `sourcesOfArchive()` also reads any zip of Markdown files (name order, images, first heading as title) and bounds what it inflates. `Import…` (`#import`, `#importFile`) opens a PDF, an HTML, a Markdown, a zip or a project file, told apart by content in `sourcesOfFile()` (`%PDF-`, `PK` for a zip, `<html`, `{` for JSON, anything else is Markdown) and applied through `loadSources()` and the usual `applyConfig()` path. `src/markdown-sources.js` (plain ESM around `yaml`, loaded on demand) writes `Markdown with project` (`exportMarkdown()`, desktop command `export-markdown`): `markdownWithSources({ json, markdown })` puts the project in a YAML front matter whose first key is the marker `markdown-paged-studio: 1` (heavy values last, `lineWidth: 0`, literal blocks), the body right after the closing fence; with several files the front matter lists `files: [{ name, lines }]` and the body is their assembly, cut back with `splitAssembled()`; `sourcesOfMarkdown(text)` only reads a front matter that carries the marker, otherwise the whole text is the Markdown and its first level 1 heading (`firstHeading()`, outside code fences) the title, nothing else changes (a plain `.md`, or another tool's front matter). The Markdown attachment of the PDF and the editor bar `Download this file` (named after the title when the document has one file, else the file's name) stay plain Markdown; the editor bar `#loadMarkdown` drops the studio's front matter. Browser: the print dialog cannot hand its file back, so `PDF with project` is drawn by the page (`src/pdf-render.js`, loaded on demand): each `.pagedjs_page` is cloned into an SVG `foreignObject` with the fonts (`inlineFontCss()`) and every rule of the preview (`previewCss()` in `src/render.js`, which includes the sheet Paged.js fills through the CSSOM: target counters of the table of contents), drawn on a canvas at `RENDER_SCALE` (must be a `data:` URL: an SVG from a blob URL taints the canvas), stored as PNG (JPEG when the page holds a photo) in a pdf-lib document, covered with invisible text lines measured on the live layout (`Range.getClientRects()` grouped by vertical position, zoom divided out) and link annotations; the text layer uses the glyphless font of Tesseract (`src/glyphless-font.js`, Apache 2.0) as a Type0 font with Identity-H codes (UTF-16 code units, `ToUnicode` identity), so any script of the basic plane can be searched and copied; cross-page counters are reset per page clone (`counterReset()`); the `--pagedjs-string-*` values of the running header, which Paged.js writes unclosed (`"text`) in the inline style of each page, are written again closed on the clone (`closeCssString()`), or Chromium drops them from the SVG image and the margin box comes out empty. `PDF only` and `Ctrl+P` keep the print dialog (vector). While a PDF is written (browser or desktop), `lock()` in `src/ui.js` shows the `#busy` overlay and makes `#app` inert; `progress()` reports, `unlock()` runs in `finally`. Desktop menu commands: `export-pdf` (with project), `export-pdf-plain`, `export-html`, `export-markdown`, `export-archive`, `export-project`, `import`, `print`, `welcome` and `shortcuts` (Help menu), and in the View menu `mode-edit`, `mode-split`, `mode-view`, `toggle-sidebar`, `theme-system`, `theme-light`, `theme-dark`; MCP: `project` input of `render_pdf`.
- Fonts: Inter comes from `@fontsource-variable/inter` in subsets.
