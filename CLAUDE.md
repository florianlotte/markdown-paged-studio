# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` / `npm run build` / `npm run preview` (Vite, entry is `index.html`). `vite.config.js` only defines two build-time constants, `__APP_VERSION__` (from package.json) and `__APP_COMMIT__` (`GITHUB_SHA`, else `APP_COMMIT`, else git), read through `src/version.js` and shown in the sidebar footer; the dev server shows `dev` as the commit. Restart a running dev server after editing `vite.config.js`. `PORT=5183 npm test` runs the web suite next to a dev server that already holds port 5173.
- `npm run lint` (ESLint flat config, browser globals) and `npm run format` (Prettier: 2-space, single quotes, semicolons, width 120). Both must pass before you finish.
- `npm test` runs the Playwright integration tests in `tests/studio-*.spec.js`, one file per domain (document, layout, diagrams, images, editing, features, language) with shared helpers in `tests/helpers/studio.mjs` (headless Chromium, starts Vite itself; one-time `npx playwright install chromium --only-shell`). Run a single test with `npx playwright test -g "part of its title"`. Most of the app needs a browser (Paged.js, FileReader, Blob URLs); the pure Markdown, image and font helpers have unit tests in `tests/markdown.test.mjs`, `tests/images.test.mjs` and `tests/fonts.test.mjs`, next to `tests/repo.test.mjs` for the changelog and `tests/conformance.test.mjs` for the Markdown conformance (`npm run test:unit`). Use `/verify-preview` for visual checks. `npm run screenshots` (after `npm run build`) retakes the README screenshots with `scripts/screenshots.mjs`; run it when the look of the studio or of the sample document changes, from a build without personal files in `local/`. A dev or preview server started for a check must be stopped afterwards (never the user's own server on port 5173).
- Desktop build: `electron/main.js` (ESM) serves `dist/` over the private `app://studio` scheme and exposes only `window.desktop.exportPdf` and `window.desktop.onCommand` (File menu) through `electron/preload.cjs` (sandboxed renderer). `standaloneHtml({ mode })` takes `export`, `print` or `pdf`. `#exportPdf` is the only PDF button: `exportPdf()` picks the direct desktop path or `openPrintWindow()` (browser print dialog), which must stay inside a user gesture (click, Ctrl+P) with `window.open` before its first `await`; the desktop test is `npm run test:desktop` (needs `npm run build` first, own config `playwright.desktop.config.js`). Packaging: `electron-builder.yml`, output in `release/`.
- MCP server: `mcp/server.mjs` (stdio, `@modelcontextprotocol/sdk` + Playwright) renders through `dist/` using the page automation API `window.studio` from `src/automation.js` (`defaults()`, `schema()`, `render(config, mode, { images })`). Keep that API and the zod `configShape` of the server in sync with `CONFIG_SCHEMA`. `MPS_OUTPUT_DIR` confines the tools' writes, `MPS_INPUT_DIR` the image files they read, and existing files are only replaced with `overwrite: true`. Test: `npm run test:mcp` after `npm run build` (Node test runner, real MCP client over stdio).
- Releasing: move the `Unreleased` entries of `CHANGELOG.md` under `## [x.y.z] - date`, add its compare link at the bottom, and bump `package.json` to the same version (`tests/repo.test.mjs` fails otherwise); the release notes are cut from that section by `scripts/release-notes.mjs`. Describe every user-visible change under `Unreleased` as part of the change itself.
- Workflows: `ci.yml` is also a reusable workflow. `release-desktop.yml` waits for the CI run of the tagged commit (`gate` job) and only calls `ci.yml` itself (`checks` job) when the commit has none, before building, and `pages.yml` runs on `workflow_run` after a successful CI on `main`, so nothing is deployed or released from a commit that fails the tests. Keep the workflow name `CI`: `pages.yml` refers to it.

## Constraints

- 100 % client-side: no backend, no env vars. Personal defaults come from the gitignored `local/` folder, read at build time with `import.meta.glob` and merged into `DEFAULTS` (never into `DEFAULT_STATE`); use `DEFAULTS` for anything that resets or initializes the document. The document autosaves to localStorage (`STORAGE_KEY`), except `logoDataUrl`, which is saved in IndexedDB (`restoreLogo()`, `saveLogo()`; still a plain state key in the config JSON and the MCP config), and every config that enters the state (JSON import, restore) goes through `sanitizeConfig()`, which whitelists keys and coerces values. A new state key needs: a default in `DEFAULT_STATE`, a kind in `CONFIG_SCHEMA` (validated in `sanitizeConfig()`), a form control with the same `id` in `index.html` (bound automatically by `bindInputs()`), its French label in `src/i18n.js`, and an entry in the MCP `configShape`.
- Module map (`src/`): `config.js` (constants, defaults, personal `local/` defaults merged into `DEFAULTS`, the mutable `state`, `sanitizeConfig()`, autosave), `markdown.js` (markdown-it + Mermaid → `renderDiagrams()`; fence attributes `width`/`align`/`caption` via `parseDiagramAttributes()` and `updateFenceAttributes()`; `\newpage` and `[[toc]]` block rules, heading anchors, footnotes, task lists, `www.` links, `highlightCode()`), `images.js` (image library: `imageKey()` matching by file name, IndexedDB persistence, upload with downscaling, `sanitizeImages()`; no browser access at import time so it is unit-testable), `editor.js` (`editInPlace()` and `insertBlock()`: every edit the studio makes to the Markdown editor, kept in its undo history), `i18n.js` (interface language), `fonts.js` (the bundled Inter font: `loadPreviewFonts()` before pagination, `inlineFontCss()` for exports; subset choice in the pure `font-faces.js`), `resize-controls.js` (studio-only resize controls added to diagrams and images of the preview after each render, one `TARGETS` entry per kind), `document.js` (`documentCss()`, `documentHtml()`, `standaloneHtml({ mode })`), `render.js` (Paged.js preview lifecycle, `scheduleRender()`), `view.js` (layout and zoom: the `view` object, own localStorage key, `applyView()` must run after every successful render; zoom is the CSS `zoom` property on `#preview`), `ui.js` (form binding, tabs, files, export, print, desktop bridge), `automation.js` (`window.studio` for the MCP server, `?automation=1` skips the initial preview), `escape.js`, and `main.js` as the entry point. The markup lives in `index.html`; `src/ui.css` styles the studio chrome only; the rendered document is styled solely by `documentCss()`.
- Language: README, comments, docs and the UI strings in the code and markup are all English. The interface is also available in French: `src/i18n.js` holds the translations keyed by the English text, translates the static markup in place (text nodes and `title`, `aria-label`, `placeholder`, `alt`) and exposes `t()` for strings set from JavaScript. Add the French entry whenever you add or change a UI string, write dynamic strings with `t('… {name}', values)`, and rebuild them in an `onLanguageChange()` listener. The interface language is a studio setting (own localStorage key), never part of the document config. Tests run in English (Playwright default locale; the desktop test passes `--lang=en-US`). The sample date uses the browser locale (`Intl.DateTimeFormat(undefined, …)`).
- The CSS class contract for user stylesheets is documented in README (section Custom CSS) and is public API: the cover and content classes (`.document-content`, `.cover-page`, `.cover-logo`, `.cover-title`, `.cover-subtitle`, `.cover-meta`), and inside the content the diagram, image, caption, table of contents, page break and code block classes, plus the `sec-` heading ids. Do not rename any of them. The same contract is served by the MCP resource `studio://css-contract`: update both. Load the `paged-css` skill before editing layout, `@page`, or export code.

## Paged.js gotchas

- Preview creates a fresh `new Previewer()` per render (220 ms debounce) into a hidden but attached `.render-stage`, then swaps the pages into `#preview`. A newer render stops the pending one with `chunker.stop()`, and `disposePreviewer()` removes the `<style>` each Previewer injects into `<head>`. Never render straight into `#preview`. CSS is handed to Paged.js as a Blob URL.
- Print and HTML export (`standaloneHtml()`) inline `paged.polyfill.min.js` from node_modules through a Vite `?raw` import, so the export works offline and always matches the bundled version. The print window prints itself from `PagedConfig.after`, never from a timer.
- markdown-it runs with `html: false`: raw HTML in Markdown is intentionally stripped.
- Mermaid diagrams are rendered to inline SVG in `renderDiagrams()` before pagination and are part of the HTML handed to Paged.js and to the export. `documentHtml()` and `standaloneHtml()` are async; the print handler must call `window.open` before its first `await` or pop-up blockers will stop it.
- Diagram size lives in the Markdown (` ```mermaid width=60% align=left `), never in UI state: the preview controls rewrite that fence line through `updateFenceAttributes()` using the placeholder's `data-line`. Target a diagram's drawing with `.mermaid-diagram > svg` (the controls contain icon SVGs), and keep the controls out of `documentHtml()`. While a render is pending the preview is `.is-stale` and the controls are inert. The controls show on hover (with a CSS bridge over the gap to the toolbar and a grace delay through `visibility` transitions, never `pointer-events: none`) and stay open on the clicked diagram (`.is-selected`, remembered by source line across renders). Test pointer travel with `page.mouse.move(..., { steps })` after scrolling the diagram into view: `hover()` and `click()` teleport and hide this class of bug.
- Images never use their path: the `image` rule of `src/markdown.js` resolves the file name through `findImage()` and inlines the data URL, or renders `.image-missing`. They live outside `state` (IndexedDB, plus the `images` key of the config JSON), so extend `exportImages()`/`replaceImages()` rather than `CONFIG_SCHEMA`. Size and alignment are written in braces after the image and rewritten by `updateImageAttributes()` from `data-line`, `data-line-end` and `data-index` (table cells have no source map: their images use the line of their row and a rank across the row). `.is-block` (alone in its paragraph, links ignored) is centered by default; an image inside text floats with `align=left|right` and takes its own line with `align=center`. In `resize-controls.js` measure against `columnBox()` (content box of the nearest non-inline ancestor), never `parentElement`.
- Editing the Markdown for the user: anything the studio writes into the editor goes through `src/editor.js`. `editInPlace()` writes the smallest changed range with `document.execCommand('insertText')`, the only way to keep the undo history of a textarea, and gives the focus back to where it was; `insertBlock()` builds on it for the insert buttons and pasted images. Assigning `editor.value` or calling `setRangeText()` wipes the history: they are only the fallback when the editor is hidden and cannot take the focus. Preview edits (`applyMarkdown()` in `src/render.js`) are also recorded in a history of their own, so Ctrl+Z / Ctrl+Y outside text fields undo and redo them as long as the source was not edited since. A handle driven from the keyboard is refocused after the render (`keyboardKey`).
- Links of the preview never navigate: `bindPreviewLinks()` in `src/ui.js` opens `http(s)` and `mailto` links in a new tab (the system browser on desktop), scrolls to the target of an anchor (`#sec-…`) and ignores relative links.
- Markdown conformance: `scripts/conformance.mjs` (`npm run conformance`) runs the CommonMark examples (`commonmark-spec`) and the GFM extension examples (`tests/fixtures/gfm-extensions.json`) through `md`. Every difference with CommonMark must belong to a cause listed in `CAUSES` (raw HTML off, images by file name, typographer, linkify); `tests/conformance.test.mjs` fails on a difference without cause and names the examples. A new markdown-it rule must therefore only react to its own marker: check with `npm run conformance`. When a difference is wanted, or when a syntax becomes supported, update `CAUSES` or the probes, the recorded figures of the test and `docs/markdown-support.md` (`npm run conformance -- --write`, then `npm run format`). Block rules registered before `paragraph` run after `hr`, `list`, `heading`: they cannot take over those syntaxes.
- Document features: heading ids are prefixed (`ANCHOR_PREFIX`, `sec-`) because the preview lives in the studio page, where a heading named "Status" would otherwise shadow `#status`; `[text](#slug)` links are rewritten to the prefixed id. `[[toc]]` lists the headings after it and gets its page numbers from `target-counter()`, which Paged.js turns into a `counter-reset` on the `::after` of each link. Captions are plain text (no automatic numbering: CSS counters restart on every page box). Highlighting is a post-processing step like `renderDiagrams()`, with highlight.js loaded on first use; theme colours live in `documentCss()` after the user CSS and must not use italic (it would pull the italic font files into every export). Mirrored margins use `@page :left` plus `@page cover:left` so the cover stays bare.
- Footnotes use `markdown-it-footnote` for the parsing only: the rule `footnote_notes` removes the block of notes the plugin puts at the end, and `footnote_ref` writes the text of the note in place as `<span class="footnote">`, which `float: footnote` sends to the foot of the page. Paged.js numbers calls and notes with CSS counters, in document order; a repeated call is a plain `.footnote-ref` with the number of the first one. The call is an `<a>` that carries the class of the note, so style it through `.footnote::footnote-call`. `src/ui.css` resets the form styles inside `.preview` (`all: revert` on `input`), otherwise the check boxes of task lists take the look of the studio fields.
- Known Paged.js limit: a single paragraph longer than about two pages makes the layout loop ("Layout repeated" in the console, far too many pages). It comes from Paged.js 0.4.3, not from the studio; keep test documents made of several paragraphs.
- Editable exports: `src/pdf-sources.js` (plain ESM around pdf-lib, loaded on demand in the page, imported by the MCP server) attaches `markdown-paged-studio.json` (the Save config JSON: `sourceJson()` in `src/ui.js`, `window.studio.source()` for the server) and `document.md` to a PDF, and reads the JSON back. The HTML export carries the same JSON in `<script type="application/json" id="markdown-paged-studio-source">` (`standaloneHtml({ source })`, `sourcesOfHtml()`). `Load config` accepts JSON, PDF and HTML through `sourcesOfFile()` and the usual `applyConfig()` path. Desktop: the package has no node_modules, so `export-pdf` returns the bytes and a one-shot token for the chosen path, the page attaches the sources, and `write-pdf` writes them; the page never sees the path. `Export` is a split button (`#exportDefault`, `#exportMenu`, `#exportOptions`): the main part and `Ctrl+Shift+E` / `Ctrl+P` export the PDF with the project; the menu offers `PDF with project`, `PDF only`, `HTML with project` and `Project only` (`exportPdf({ project })`, `exportHtml()`, `exportProject()` in `src/ui.js`). `Import…` (`#import`, `#importFile`) opens a PDF, an HTML or a project file, told apart by content in `sourcesOfFile()`. Browser: the print dialog writes outside the studio, so a banner (`#projectBanner`) then asks for the saved PDF and gives it back with the project. Desktop menu commands: `export-pdf` (with project), `export-pdf-plain`, `export-html`, `export-project`, `import`; MCP: `project` input of `render_pdf`.
- Fonts: Inter comes from `@fontsource-variable/inter` in subsets. Only the subsets the document text needs are registered (FontFace API) and awaited before pagination, and the same ones are inlined in exports inside `<style data-pagedjs-ignore>` so Paged.js does not parse the font data. Never add `@font-face` rules with all subsets to the page: Paged.js loads every declared face before laying out.
- Any user string injected into `@page` margin boxes must go through `escCssString()`; any injected into HTML must go through `escapeHtml()`.
- `.cover-page` takes its height from `PAGE_HEIGHT_MM[state.pageSize]` so it fills exactly one page on A4, A5 and Letter; keep that map in sync with `PAGE_SIZES`.
