# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` / `npm run build` / `npm run preview` (Vite, entry is `index.html`). `vite.config.js` only defines two build-time constants, `__APP_VERSION__` (from package.json) and `__APP_COMMIT__` (`GITHUB_SHA`, else `APP_COMMIT`, else git), read through `src/version.js` and shown in the sidebar footer; the dev server shows `dev` as the commit. Restart a running dev server after editing `vite.config.js`. `PORT=5183 npm test` runs the web suite next to a dev server that already holds port 5173.
- `npm run lint` (ESLint flat config, browser globals) and `npm run format` (Prettier: 2-space, single quotes, semicolons, width 120). Both must pass before you finish.
- `npm test` runs the Playwright integration tests in `tests/studio-*.spec.js`, one file per domain (document, layout, diagrams, images, editing) with shared helpers in `tests/helpers/studio.mjs` (headless Chromium, starts Vite itself; one-time `npx playwright install chromium --only-shell`). Run a single test with `npx playwright test -g "part of its title"`. Most of the app needs a browser (Paged.js, FileReader, Blob URLs); the pure Markdown, image and font helpers have unit tests in `tests/markdown.test.mjs`, `tests/images.test.mjs` and `tests/fonts.test.mjs` (`npm run test:unit`). Use `/verify-preview` for visual checks.
- Desktop build: `electron/main.js` (ESM) serves `dist/` over the private `app://studio` scheme and exposes only `window.desktop.exportPdf` and `window.desktop.onCommand` (File menu) through `electron/preload.cjs` (sandboxed renderer). `standaloneHtml({ mode })` takes `export`, `print` or `pdf`. `#exportPdf` is the only PDF button: `exportPdf()` picks the direct desktop path or `openPrintWindow()` (browser print dialog), which must stay inside a user gesture (click, Ctrl+P) with `window.open` before its first `await`; the desktop test is `npm run test:desktop` (needs `npm run build` first, own config `playwright.desktop.config.js`). Packaging: `electron-builder.yml`, output in `release/`.
- MCP server: `mcp/server.mjs` (stdio, `@modelcontextprotocol/sdk` + Playwright) renders through `dist/` using the page automation API `window.studio` from `src/automation.js` (`defaults()`, `schema()`, `render(config, mode)`). Keep that API in sync with `CONFIG_SCHEMA`. `MPS_OUTPUT_DIR` confines the tools' writes, `MPS_INPUT_DIR` the image files they read, and existing files are only replaced with `overwrite: true`. Test: `npm run test:mcp` after `npm run build` (Node test runner, real MCP client over stdio).
- Workflows: `ci.yml` is also a reusable workflow. `release-desktop.yml` calls it (`checks` job) before building, and `pages.yml` runs on `workflow_run` after a successful CI on `main`, so nothing is deployed or released from a commit that fails the tests. Keep the workflow name `CI`: `pages.yml` refers to it.

## Constraints

- 100 % client-side: no backend, no env vars. Personal defaults come from the gitignored `local/` folder, read at build time with `import.meta.glob` and merged into `DEFAULTS` (never into `DEFAULT_STATE`); use `DEFAULTS` for anything that resets or initializes the document. The document autosaves to localStorage (`STORAGE_KEY`), except `logoDataUrl`, which is saved in IndexedDB (`restoreLogo()`, `saveLogo()`; still a plain state key in the config JSON and the MCP config), and every config that enters the state (JSON import, restore) goes through `sanitizeConfig()`, which whitelists keys and coerces values. Extend `CONFIG_SCHEMA` when adding a state key.
- Module map (`src/`): `config.js` (constants, defaults, personal `local/` defaults merged into `DEFAULTS`, the mutable `state`, `sanitizeConfig()`, autosave), `markdown.js` (markdown-it + Mermaid → `renderDiagrams()`; fence attributes `width`/`align` via `parseDiagramAttributes()` and `updateFenceAttributes()`), `images.js` (image library: `imageKey()` matching by file name, IndexedDB persistence, upload with downscaling, `sanitizeImages()`; no browser access at import time so it is unit-testable), `fonts.js` (the bundled Inter font: `loadPreviewFonts()` before pagination, `inlineFontCss()` for exports; subset choice in the pure `font-faces.js`), `resize-controls.js` (studio-only resize controls added to diagrams and images of the preview after each render, one `TARGETS` entry per kind), `document.js` (`documentCss()`, `documentHtml()`, `standaloneHtml({ mode })`), `render.js` (Paged.js preview lifecycle, `scheduleRender()`), `view.js` (layout and zoom: the `view` object, own localStorage key, `applyView()` must run after every successful render; zoom is the CSS `zoom` property on `#preview`), `ui.js` (form binding, tabs, files, export, print, desktop bridge), `automation.js` (`window.studio` for the MCP server, `?automation=1` skips the initial preview), `escape.js`, and `main.js` as the entry point. The markup lives in `index.html`; `src/ui.css` styles the studio chrome only; the rendered document is styled solely by `documentCss()`.
- Language: UI strings, README, comments and docs are all English. The sample date uses the browser locale (`Intl.DateTimeFormat(undefined, …)`).
- The CSS class contract for user stylesheets (`.document-content`, `.cover-page`, `.cover-logo`, `.cover-title`, `.cover-subtitle`, `.cover-meta`) is documented in README and is public API. Do not rename those classes. Load the `paged-css` skill before editing layout, `@page`, or export code.

## Paged.js gotchas

- Preview creates a fresh `new Previewer()` per render (220 ms debounce) into a hidden but attached `.render-stage`, then swaps the pages into `#preview`. A newer render stops the pending one with `chunker.stop()`, and `disposePreviewer()` removes the `<style>` each Previewer injects into `<head>`. Never render straight into `#preview`. CSS is handed to Paged.js as a Blob URL.
- Print and HTML export (`standaloneHtml()`) inline `paged.polyfill.min.js` from node_modules through a Vite `?raw` import, so the export works offline and always matches the bundled version. The print window prints itself from `PagedConfig.after`, never from a timer.
- markdown-it runs with `html: false`: raw HTML in Markdown is intentionally stripped.
- Mermaid diagrams are rendered to inline SVG in `renderDiagrams()` before pagination and are part of the HTML handed to Paged.js and to the export. `documentHtml()` and `standaloneHtml()` are async; the print handler must call `window.open` before its first `await` or pop-up blockers will stop it.
- Diagram size lives in the Markdown (` ```mermaid width=60% align=left `), never in UI state: the preview controls rewrite that fence line through `updateFenceAttributes()` using the placeholder's `data-line`. Target a diagram's drawing with `.mermaid-diagram > svg` (the controls contain icon SVGs), and keep the controls out of `documentHtml()`. While a render is pending the preview is `.is-stale` and the controls are inert. The controls show on hover (with a CSS bridge over the gap to the toolbar and a grace delay through `visibility` transitions, never `pointer-events: none`) and stay open on the clicked diagram (`.is-selected`, remembered by source line across renders). Test pointer travel with `page.mouse.move(..., { steps })` after scrolling the diagram into view: `hover()` and `click()` teleport and hide this class of bug.
- Images never use their path: the `image` rule of `src/markdown.js` resolves the file name through `findImage()` and inlines the data URL, or renders `.image-missing`. They live outside `state` (IndexedDB, plus the `images` key of the config JSON), so extend `exportImages()`/`replaceImages()` rather than `CONFIG_SCHEMA`. Size and alignment are written in braces after the image and rewritten by `updateImageAttributes()` from `data-line`, `data-line-end` and `data-index` (table cells have no source map: their images use the line of their row and a rank across the row). `.is-block` (alone in its paragraph, links ignored) is centered by default; an image inside text floats with `align=left|right` and takes its own line with `align=center`. In `resize-controls.js` measure against `columnBox()` (content box of the nearest non-inline ancestor), never `parentElement`.
- Preview edits go through `applyMarkdown()` in `src/render.js`, which writes the smallest changed range into the editor with `document.execCommand('insertText')`: assigning `editor.value` wipes the undo history (it remains the fallback when the editor is hidden). Every preview edit is also recorded in a history of its own, so Ctrl+Z / Ctrl+Y outside text fields undo and redo it as long as the source was not edited since. The focus returns to where it was, and a handle driven from the keyboard is refocused after the render (`keyboardKey`). Links of the preview never navigate: `bindPreviewLinks()` in `src/ui.js` opens `http(s)` and `mailto` links in a new tab (the system browser on desktop) and ignores anchors and relative links.
- Fonts: Inter comes from `@fontsource-variable/inter` in subsets. Only the subsets the document text needs are registered (FontFace API) and awaited before pagination, and the same ones are inlined in exports inside `<style data-pagedjs-ignore>` so Paged.js does not parse the font data. Never add `@font-face` rules with all subsets to the page: Paged.js loads every declared face before laying out.
- Any user string injected into `@page` margin boxes must go through `escCssString()`; any injected into HTML must go through `escapeHtml()`.
- `.cover-page` takes its height from `PAGE_HEIGHT_MM[state.pageSize]` so it fills exactly one page on A4, A5 and Letter; keep that map in sync with `PAGE_SIZES`.
